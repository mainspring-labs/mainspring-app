[Mainspring contracts](https://github.com/mainspring-labs/mainspring-contracts) let one Stellar contract (a *spring*) control the code of a whole fleet of contracts through a CAP-85 executable reference. Upgrades wait out a timelock, and any instance owner can `pin` their instance to opt out before the upgrade lands.

That opt-out only helps if people know an upgrade is coming. This repo is the reading side:

- **`@mainspring-labs/sdk`** gives typed reads of springs, factories and instances. It tells you whether a contract follows a fleet or runs fixed code, and it decodes and scans every Mainspring event.
- **`mainspring` CLI** prints fleet reports and per-instance pin advice, and `watch` streams fleet events with alerts on proposals.

## Try it on testnet

The contracts' [v0.1.0 release](https://github.com/mainspring-labs/mainspring-contracts/releases/tag/v0.1.0) has a live testnet fleet: one pinned instance and one following the tag.

```bash
git clone https://github.com/mainspring-labs/mainspring-app
cd mainspring-app
pnpm install
pnpm build

node apps/cli/dist/main.js fleet CAE74DKXJYMTZ6OJ6DF2Q6DTFPBDUXOZENUJQK2GZFWSNQPJE4UA7XUS
```

## CLI

| Command | What it shows |
|---|---|
| `mainspring fleet <factory>` | Spring, admin, guardian, current and previous code, timelock, pending proposal with countdown, every instance and whether it follows or is pinned |
| `mainspring tag <spring> <tag>` | Tag state, pending proposal, full version history |
| `mainspring instance <contract>` | Who controls this contract's code. If an upgrade is pending, the deadline to call `pin()` |
| `mainspring watch <factory>` | Polls the spring, factory and every instance for events, and picks up new instances as they deploy |

`--json` prints machine-readable output. `--network mainnet --rpc <url>` targets mainnet. SDF runs no public mainnet RPC, so bring a provider URL.

## SDK

```ts
import { fleetReport, inspectInstance, rpcServer, scanEvents, TESTNET } from "@mainspring-labs/sdk";

const report = await fleetReport(factoryId, TESTNET);
if (report.pending) {
  console.log(`upgrade to ${report.pending.wasmHash} lands at ${report.pending.eta}`);
}

const status = await inspectInstance(rpcServer(TESTNET), contractId);
// { mode: "following", owner, tag, wasmHash } | { mode: "fixed", wasmHash } | { mode: "stellar-asset" }

const { events, cursor } = await scanEvents(rpcServer(TESTNET), {
  contractIds: [springId, factoryId],
  startLedger,
});
```

The SDK ships the contract interfaces of mainspring-contracts v0.1.0, generated by [`packages/sdk/scripts/gen-spec.sh`](packages/sdk/scripts/gen-spec.sh) from the release Wasm after checking it against the release `SHA256SUMS`. It never fetches a contract's interface from the network, so a contract at a given address can't change what the SDK thinks it is calling.

`scanEvents` follows RPC cursors until it reaches the latest ledger. RPC scans a bounded ledger window per request and can return an empty page with a cursor that has moved forward, so stopping at the first empty page would miss events.

## Layout

```
packages/sdk     @mainspring-labs/sdk: readers, instance inspection, events, fleet report
apps/cli         mainspring CLI
```

A web dashboard and an indexer are planned. See the [issues](https://github.com/mainspring-labs/mainspring-app/issues).

## Development

Node 22+ and pnpm 11.

```bash
pnpm install
pnpm build        # the CLI imports the SDK's build output
pnpm typecheck
pnpm test         # unit tests
MAINSPRING_LIVE=1 pnpm --filter @mainspring-labs/sdk test   # plus live testnet tests
```
